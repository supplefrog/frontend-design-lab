# Cloud continuation

Continue project work in its compatible configured native Codex cloud environment by default. Reuse the repository-linked `frontend-design-lab` environment; use the user's PC when local applications, files or hardware are required. Verify the environment and repository binding before dispatch. A one-off sandbox does not replace the reusable environment, and trivial questions need no new task.

Read `docs/CONTINUATION.md` before editing. Preserve both examples and their selected reference images. Use the accepted craft level as the minimum for new generations without turning the palette, physical metaphor or component shapes into a universal theme. The workflow should find consequential defects before asking the user to identify them. Passing source tests is separate from rendered quality and taste approval.

This repository supplies relevant skill snapshots under `.agents/skills`. Read `frontend-ui-engineering/SKILL.md`, its defect-acceptance, material-reconstruction and motion references for UI work; read other skills only when their procedures apply. Record actual skill/support-file reads and hashes in the cloud receipt. Do not assume local skills, browser state or Windows applications were inherited.

Before designing or structurally repairing an AI workflow, read `.agents/skills/outcome-first-workflow-design/SKILL.md` and assess researched mechanisms against the intended human outcome before selecting a repair. Reuse current source-bound research when it settles the decision.

Read `.agents/context/core.md` before delegation and `.agents/context/code-verification.md` before nontrivial code review. These are pinned execution preferences; their Windows source locations are provenance, not paths to use in cloud. The repository's supplied snapshots are project-local context. Shared instruction changes belong in canonical Agent Sync and its official reconciliation lane, not a direct edit of deployed copies.

At cloud start, read the host-provided cloud runtime skill when available and inspect the available environment status, platform, disk, browser/rendering support, GPU, dependencies and lifetime. Host-bundled runtime/image-tool guides are not redistributed without verified public terms. Use the supported runtime's actual tools and network policy. No paid cloud rental, paid API fallback, credential extraction or unapproved model change. Native authenticated image generation remains authorized when available; an unavailable tool is a dependency to report, not permission to replace it with a paid route.

Run relevant production tests and ordinary browser tasks. Bind observations to current source hashes; test complete motion, direct control input, repeated/no-op activation and the affected surrounding geometry. A consequential reference reconstruction or repeated narrow-check failure needs bounded fresh scrutiny under the existing frontend owner. The parent resolves evidence-backed findings and verifies fixes; do not introduce an endless review swarm or fixed case quota. Stop when the scoped criteria hold, and state remaining uncertainty.

Use `work/cloud-run` for new scratch. At closeout, preserve authoritative source, context and referenced evidence first, then inventory exclusively owned stale scratch and duplicates and archive recoverably. Same-volume recovery copies do not free disk. Check paths, hashes, references and active writers before removal; preserve uncertain ownership, original references, vendor applications and unfinished work. Retain a small archive/restore receipt. Export cloud artifacts before teardown and commit meaningful source changes to this repository through its authorized GitHub connection; never treat an ephemeral cloud path as the only recovery copy.
